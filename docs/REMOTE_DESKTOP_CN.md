# 轻量电脑画面

主页面右上角、文件夹右侧的电脑图标用于用户本人查看、点击 Windows 桌面及 UAC 弹窗。“电脑桌面”与文件选择页面共用卡片样式和遮罩，点击卡片外关闭并断开串流；无关闭、重连、放大按钮，关闭后重新打开即可重新连接。标题支持中文、英文、日文。现有 Cua 仍负责 Agent 操作，这个入口不提供 MCP 工具，不提升 BigaCli/Codex 的权限。

入口仅在手机和平板浏览器显示，按设备系统标识判断，包含使用桌面模式的 iPad，不按窗口宽度判断。Windows 触屏电脑仍按电脑处理。电脑端不轮询桌面状态，不显示授权窗口提醒，也不能通过其他页面入口打开。此限制用于界面体验，不作为服务端身份认证。

手机双指捏合以两指之间的位置为中心缩放本地串流画面，双指拖动移动放大后的画面，不再向电脑发送 Ctrl＋滚轮或双指滚动。单指点击/拖动及双指轻点右键保持原有行为；捏合缩小或重新打开恢复全景。使用固定 noVNC 1.7.0 的 display 缩放同步维护远端点击坐标，不修改 vendor 文件。

电脑画面不提供自动向对话发送消息的按钮。人工处理完成后可直接关闭画面，按需自行在对话中发送消息。

工具结果出现明确的 `blocked by policy` 文本时，页面显示策略拒绝提示和电脑画面入口；它不是额外授权按钮，不自动重试、换工具执行或发起提权。原生审批继续使用现有审批卡片；连接中断时保留卡片。权限选择页显示 CLI 配置返回的 approval_policy / approvals_reviewer，未显式返回时标明默认，不能冒充当前轮次的实际审批结果。

首次点击“启用电脑画面”，需要人在电脑端允许 Windows 安装授权。随后 UltraVNC 小型服务随 Windows 启动，仅监听 127.0.0.1 的独立端口。浏览器通过 BigaCli 当前地址的 WebSocket 访问，不需要开放 VNC 防火墙端口。继承 BigaCli 现有单用户、可信网络使用边界，不提供新的公网登录系统。

检测到 consent.exe 时提示并打开画面；这是授权窗口出现的提示，不判断该授权是否应当通过。用户自行选择“是”或“否”。关闭面板即断开串流；同一个授权窗口不会反复弹出面板。检测仅在网页可见时轮询，多个页面共用短时服务端查询缓存。状态查询失败会显示错误，不推断已授权。

服务安装到 Program Files/BigaCliRemoteDesktop，连接配置独立保存在当前 Windows 用户 LocalAppData/BigaCli/remote-desktop。切换 Codex 账号、更新 BigaCli 不重新安装服务或改变连接配置。服务属于 Windows 管理的常驻组件，BigaCli 退出后仍在本机待命；网页桥随 BigaCli 退出而关闭。可在 Windows 服务管理器中停止/禁用 BigaCli remote desktop；卸载服务需管理员执行 `sc.exe delete BigaCliRemoteDesktop`（先停止服务）。

依赖为未修改的 UltraVNC 1.8.3.0 x64 和 noVNC 1.7.0，运行文件及许可证保留在 custom/server/modules/remote-desktop/vendor。标准 build 会随 custom 目录复制；无需 npm 安装、不新增 Node 依赖。文件级增量更新仅下载变更文件。不要打包本机 connection.json、setup.ini、测试密码或桌面截图。

验证：隔离端口通过真实 VNC 连接、手机尺寸适配、关闭断开与重连、缩放、中英日界面、跨来源拒绝及一次性连接凭据测试。授权提示的自动打开/关闭行为使用模拟检测结果验证；真实 UAC 画面和点击“否”在前一轮临时服务验证通过。真实手机点击“是”、正式服务安装以及重启 Windows 后运行尚待完成，不以浏览器模拟冒充真机验证。
